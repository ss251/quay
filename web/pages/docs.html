Quickstart

You need Node 20 or newer. The account is on testnet. The faucet creates it. Keys stay in ~/.near-credentials/testnet/ and are not written into the project.

npm install -g ./cli
quay init
quay deploy ./dist -m "first landing"
quay promote 1
quay open

quay init writes quay.json with the account, the testnet RPC, and the gateway. Later commands read that file from the current directory or a parent.

The preview for release 1 is https://<account>.testnet.page/r/1/. After promote, the same files are also at the host root. An extra host label, such as www.<account>.testnet.page, fails TLS. Use the account host only.

CI

Create a publish-only key on your machine:

quay keys create --ci

The secret is printed once. Store it as the GitHub Actions secret QUAY_CI_KEY. Store the account id as QUAY_ACCOUNT. Do not commit the key.

The composite action in action/ runs quay deploy --ci --yes. The example workflow is examples/harbour/.github/workflows/preview.yml. A job that uses that key can upload a preview. quay promote exits 3 and does not send the call.

How it works

The contract account is the only account that can write. put_chunk stores up to 200,000 bytes under their sha256. seal records a release: the file list, the message, the byte count, and whether unknown paths should serve index.html. A chunk used by two releases is stored once. If sealing fails, an owner key drops the chunks that deploy just uploaded. A publish-only key cannot drop them, because that call needs 1 yoctoNEAR.

promote sets the production id and keeps the previous id. rollback swaps them. delete removes a release that is not production. When the last reference to a chunk is gone, the bytes are removed and the locked NEAR unlocks on the contract account. It is not transferred to you.

The public gateway calls web4_get. Production responses use public, max-age=0, must-revalidate. A path under /r/<id>/ uses a year-long immutable cache. A folder path serves index.html inside that folder. If the release was sealed with --spa, an unknown path serves the root index.html. Otherwise 404.html is served with status 404 when that file exists.

NEAR locks 0.01 NEAR per 1000 bytes of storage, which is about 1 NEAR per 100 KB, plus a small amount for each trie record. The CLI adds 80 bytes per new chunk and 200 bytes for the release when it prints the estimate. Gas is small next to that lock. The contract code itself is about 216 KB and locks a little over 2 NEAR when you deploy it.

Events are one log line per action, prefixed with EVENT_JSON:, standard quay, version 2.0.0.

Limits and caveats

LimitValue
Chunk1 to 200,000 bytes
File800,000 bytes, at most 4 chunks
Files in one release64
Live releases32
Payload cap2,000,000 bytes
Message200 characters, no control characters
Path1 to 180 bytes, letters, digits, . _ - /

This is testnet. The faucet is rate-limited and does not spend mainnet NEAR. There is no mainnet deploy path in the CLI.

The public site depends on the testnet.page gateway. If the gateway is down, the contract still holds the bytes, and the CLI can still read them by RPC.

A full-access key can replace the contract wasm. A release is not owner-proof against that key. The publish-only key cannot.

Dotfiles, node_modules, target, and .git are skipped. A directory release needs index.html.

About 1 NEAR is locked per 100 KB until you delete the release. Keep the site small. The contract code lock is separate and comes back only if you delete the account.
