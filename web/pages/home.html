Publish a site. Move production when you mean to.

Quay stores a folder of files on a NEAR testnet account. Each release keeps its own URL. Production is a pointer you promote or roll back.

How it works

  1. quay deploy

    Splits the folder into chunks of at most 200 KB, addressed by sha256. A file that has not changed is not uploaded again.

  2. seal

    Writes the file list, the message, and the byte count. The release id is permanent. Later deploys do not rewrite it.

  3. web4_get

    The public gateway asks your account for a path. / follows the production pointer. /r/<id>/ serves that release.

What it costs

NEAR locks 0.01 NEAR per 1,000 bytes of contract state, about 1 NEAR per 100 KB, plus a little for each trie record. Deleting a release that is not production unlocks those bytes on the contract account. The lock is not sent to your other account. The wasm is 216,419 bytes and locks a little over 2 NEAR on its own. That code lock comes back only if the account is deleted.

The harbour sample, quay-65nqd3rn.testnet, has four releases. Production is 4 and the previous release is 2. The sealed files are 9,588 bytes. The account's storage lock is 2.3558 NEAR, almost all of it the 216 KB contract. The faucet started that account near 10 NEAR. Gas, plus 0.02 NEAR sent into another contract, left 9.9720 NEAR on it, of which 7.6162 NEAR is free.

A packed quay init on a clean folder created quay-i7qkbbp3.testnet with 9.9982 NEAR. After two site releases, a rollback, a CI preview, and an agent page, the contract reports 7,674 stored bytes. A later rollback signed in the dashboard moved production to release 2. The account then held 10.0134 NEAR, of which 2.3151 NEAR was locked and 7.6983 NEAR was free. Deleting a release that is not production unlocks that release's bytes on the same account.

Why not just upload files

A sealed release stays at /r/<id>/. Promoting does not rewrite those files, so a preview URL from last week still opens that build.

quay rollback is one call. It swaps the production pointer with the previous release. You do not re-upload the old folder.

A publish-only key can run quay deploy. It cannot promote, roll back, or delete, because those calls require 1 yoctoNEAR and the key is not allowed to attach a deposit.

The bytes sit in your account. Delete a release that is not production and the storage deposit unlocks there. You can read the same bytes by RPC if the gateway is down.

Limits

This is testnet. The faucet is rate-limited. The CLI has no mainnet path and does not spend mainnet NEAR.

The public site depends on the testnet.page gateway. A new host has no TLS certificate until that gateway sees the first request. quay init and the first deploy wait, usually under two minutes. If the wait times out, the account is already live. Open the URL again in a minute.

Storage is the expensive part. Keep the site small. A full-access key can replace the wasm. A release is not owner-proof against that key.
