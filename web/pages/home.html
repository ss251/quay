Publish a site. Move production when you mean to.

Quay stores a folder of files on a NEAR testnet account. Each release keeps its own URL. Production is a pointer you can promote or roll back.

Read the docs Open the dashboard

Sixty seconds

  1. npm install -g ./cli

    From a checkout of this repo. Or run node cli/bin/quay.js without installing.

  2. quay init

    Creates a testnet account, deploys the contract, and writes quay.json.

  3. quay deploy ./dist -m "first landing"

    Uploads the folder, skips bytes already stored, and prints a preview URL.

  4. quay promote 1

    Points the site root at that release. The preview URL does not change.

What you get

A release is sealed. You can read it later at /r/<id>/. Promoting does not rewrite the files. Rolling back swaps the pointer with the previous release.

A publish-only key can upload. It cannot promote, roll back, or delete. Those calls require 1 yoctoNEAR, which that key cannot attach.

Storage costs about 0.01 NEAR per 1000 bytes, locked on the contract account until you delete a release that is not production.
