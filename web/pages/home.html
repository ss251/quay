What you trust, and how to replace it

One account holds the app. Everything else is a service that reads it, writes to it or runs code for it, and most of them have one operator today.

Start with four commands

Node 20 or newer and a checkout of the repository. The faucet funds the testnet account, and every deploy is a preview with its own URL. Move production on purpose with quay promote, and back with quay rollback.

For data, functions and routes, describe them in quay.json. quay up --dry-run prints the plan and changes nothing.

Questions

Is this on mainnet?

No. Quay runs on NEAR testnet only, the CLI refuses any other network, and nothing here holds real funds. Test USDC is usdc.fakes.testnet, which anyone can mint.

Do I need to sign up?

No. There is no Quay account. quay init asks the testnet faucet for a NEAR account and deploys the contract to it. The account and its keys are yours.

What happens if the gateway is down?

The pages and data stay on chain; only that door is closed. Run quay gateway --account <id> and the same site answers at 127.0.0.1:8787, or deploy the Workers build. testnet.page did fail on Nov 10, which is why the mirrors exist.

Who holds the keys?

You hold the account's full-access key, in ~/.near-credentials. CI gets a publish-only key that cannot move production. Each member holds their own key. The relayer holds its own and can only spend its balance. The dashboard never holds a key.

What can it not do yet?

The schedule stops about 6 hours after each arm, and nobody re-arms it for you. Functions are Rust compiled to WASI, with no JavaScript runtime, and take 5 to 17 seconds on OutLayer. Wallet sign-in is proven with one connector, the NEAR CLI. Telegram sign-in has run only on test data, with no real bot. A full-access key can replace the contract, so a release is not owner-proof against it.

Is Quay a NEAR product?

No. Quay is an independent hackathon project built on NEAR. NEAR and the other tools named here do not run or endorse it.
