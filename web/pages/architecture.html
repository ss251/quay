Architecture

One contract account holds the site. Everything else is a service that reads it, writes to it, or runs code for it. This page lists which is which, and what breaks when a service goes away.

What is on chain

The contract account stores these, and an RPC node can read them without any Quay service:

Releases and the production pointerlive
Docs, collections and their rulespending deploy
Routes and templates, sealed in a releasepending deploy
Memberspending deploy
Products and receiptspending deploy
Function registry and function resultspending deploy
Cron jobs and the yield chainpending deploy

Large files are the exception. The release stores a CID and a sha256, and the bytes live elsewhere.

Versioned per release, and not

A release seals three things together: files, routes and templates. quay rollback swaps all three.

These are live state and a rollback does not touch them: docs, collection rules, products, members, receipts, function code and secrets, the relay settings, and cron jobs. quay up and quay rollback print this so nobody expects a data rollback.

Run it yourself

With your own RPC, quay gateway and, for the writes that need it, quay relay serve, nothing between you and the chain belongs to someone else. Functions and large files are the two layers that still lean on a third party today.

Everything here is testnet. Read Layers for what is deployed and what is pending.
