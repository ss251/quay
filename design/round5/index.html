How a request flows

Reading a post touches only the gateway and the contract. Writing one adds the relayer and a function, and both run on OutLayer.

What you trust, and how to replace it

One account holds the app. Everything else is a service that reads it, writes to it or runs code for it, and most of them have one operator today.

PieceWhat you depend onHow to replace it
The contract on your accountReleases, routes, data, members, receipts and the function registry. Any RPC node can read them.Nothing to replace. It is yours. A full-access key can replace the wasm, so keep that key off CI.
testnet.pageOne operator serves every web4 site. We saw it answer every account with HTTP 400 for hours on Nov 10.quay gateway on your machine, the single-file build on Node, Deno or Bun, or the Workers build.
Cloudflare Workers mirrorThe owner's Cloudflare account, running the gateway unchanged.Deploy the same worker to your account with npx wrangler deploy.
OutLayerOne operator's TEE network runs functions and holds their secrets. A run takes 5 to 17 seconds.No drop-in replacement. Run the logic on your own server, as quay relay serve does, or leave functions out. Posts still land without them.
FastNEARThe default RPC, FastFS for large files, and FastData reads.Pass --rpc; the gateway falls back to other RPCs. Store large files on Pinata, Filebase or any https URL: the release keeps the sha256.
The relayerIts own account and key. Its balance is the spend limit. It cannot move the site.Run quay relay serve yourself and fund it with quay relay create.
The wallet connectorThe client loads @hot-labs/near-connect and the wallets it lists.Pass your own connector, or sign with an explicit key in Node.

Questions

Is this on mainnet?

No. Quay runs on NEAR testnet only, the CLI refuses any other network, and nothing here holds real funds. Test USDC is usdc.fakes.testnet, which anyone can mint.

Do I need to sign up?

No. There is no Quay account. quay init asks the testnet faucet for a NEAR account and deploys the contract to it. The account and its keys are yours.

What happens if the gateway is down?

The pages and data stay on chain; only that door is closed. Run quay gateway --account <id> and the same site answers at 127.0.0.1:8787, or deploy the Workers build. testnet.page did fail on Nov 10, which is why the mirrors exist.

Who holds the keys?

You hold the account's full-access key, in ~/.near-credentials. CI gets a publish-only key that cannot move production. Each member holds their own key. The relayer holds its own and can only spend its balance. The dashboard never holds a key.

What can it not do yet?

Cron is set but not armed on the Board. Functions are Rust compiled to WASI, with no JavaScript runtime, and take 5 to 17 seconds on OutLayer. Wallet sign-in has been shown once on testnet, through the NEAR CLI connector. A full-access key can replace the contract, so a release is not owner-proof against it.

Is Quay a NEAR product?

No. Quay is an independent hackathon project built on NEAR. NEAR and the other tools named here do not run or endorse it.
